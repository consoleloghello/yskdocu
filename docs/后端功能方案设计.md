# Supabase 后端功能 — 方案设计（现状 as-built）

> 更新：2026-07（重构后）。描述当前已实现的后端功能。前端直连 Supabase，无中间后端。

## 一、概述

登录用户在保留匿名体验的同时，获得跨设备云同步能力：错题、答题统计、题目笔记、纠错反馈。前端直接调用 supabase-js SDK 操作数据库，安全由 Row Level Security（RLS）保证。

## 二、技术选型

| 类别          | 选择                                     |
| ------------- | ---------------------------------------- |
| 数据库 / 认证 | Supabase（PostgreSQL + Auth + REST API） |
| 前端 SDK      | @supabase/supabase-js v2（CDN，UMD）     |
| 图表          | Chart.js v4（CDN）                       |

## 三、认证流程（实际实现）

1. **注册**：邮箱 + 密码（可选昵称）→ Supabase 发送确认邮件 → 用户输入 8 位 OTP → `verifyOtpToken(type:'signup')` 验证 → 登录。
2. **登录**：邮箱 + 密码 → `signInWithPassword`。
3. **登出**：`signOut`，清除笔记缓存，保留本地错题。
4. **session 恢复**：`getSession()` + `onAuthStateChange`（含 INITIAL_SESSION）。

> 早期设计为「白名单 + 关闭注册」，实际实现为「公开注册 + OTP 验证」。注意脚本加载顺序：`supabase.js` / `sync.js` 必须先于 `app.js`，否则登录态监听会失效。

## 四、数据表

| 表                 | 用途                             | 唯一约束                          |
| ------------------ | -------------------------------- | --------------------------------- |
| `profiles`         | 用户资料（注册时触发器自动创建） | `id` (PK)                         |
| `wrong_questions`  | 错题记录                         | `(user_id, version, question_id)` |
| `answer_history`   | 答题历史（含是否正确）           | —                                 |
| `question_notes`   | 题目笔记                         | `(user_id, version, question_id)` |
| `question_reports` | 纠错反馈（含 status）            | `(user_id, version, question_id)` |

所有表启用 RLS，用户只能读写自己的数据（`auth.uid() = user_id`）。

## 五、RPC

`get_answer_stats(p_version text)`：数据库端按章节聚合 `answer_history`（`count(*)` + `count(*) FILTER (WHERE is_correct)`），前端 `sync.js` 的 `getStats` 一次往返拿到 total / correct / byChapter，避免分页拉全表再统计。

## 六、前端模块

### `js/supabase.js`（`window.SupabaseAuth`）

- 初始化客户端、`signIn` / `signUp` / `signOut` / `verifyOtpToken`、`getUser` / `isLoggedIn` / `getClient`、`onAuthStateChange`。
- 登录弹窗 UI：登录/注册切换、验证码区、错误信息映射（中文提示）。

### `js/sync.js`（`window.Sync`）

- **错题**：`addWrongQuestion` / `removeWrongQuestion` / `getWrongQuestions`（upsert，`onConflict: user_id,version,question_id`）。
- **统计**：`recordAnswer` + `getStats`（调用 RPC）。
- **笔记**：`saveNote` / `deleteNote` / `getNotes`。
- **报错**：`submitReport`。
- 所有写操作走 `silent()` 静默失败，不阻塞 UI、不打断离线刷题。

## 七、数据流

- **登录初始化**：session 恢复 → 拉云端错题/笔记 → 合并到本地（旧 ID 自动迁移）。
- **作答**：答错 upsert 错题；答对且本地已有该错题则删除。
- **笔记 / 报错**：本地即时生效 + 云端 upsert。
- **统计**：打开统计弹窗时调用 `get_answer_stats` RPC 并渲染 Chart.js 饼图。

## 八、部署与配置

1. Supabase 项目创建后，在 SQL Editor 执行 `scripts/init_supabase.sql`（建表 + 索引 + RLS + 触发器 + RPC）。
2. `js/supabase.js` 填入 `SUPABASE_URL` / `SUPABASE_ANON_KEY`（anon key 可公开，安全靠 RLS）。
3. `.github/workflows/keepalive.yml` 每天 ping 一次，防止免费项目被 7 天无活动暂停（anon key 直接内联，其为公开密钥，安全靠 RLS）。
